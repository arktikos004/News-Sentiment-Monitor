## 結論

**判定：部分可行——可做初篩，負面仍交給語言模型**（κ 0.639，達到 0.60；負面召回率 66.4%，未達 80%）。

- 以 Gemma 4 在 2026-09-22 以前的 5,820 則評分訓練的 `bert-base-chinese`，在其後兩週的 1,370 則上，
  與 Gemma 4 的一致率為 81.8%（95% CI 79.6%–83.7%），κ 0.639。
  在兩個教師都評過的 420 則上，學生 84.5%、本機 gemma3:27b 85.5%：整體的一致程度接近「換一個語言模型」。
- 弱點在負面：Gemma 4 判為負面的 113 則，學生抓到 75 則（66.4%，CI 57.3%–74.4%）；
  漏掉的 38 則中，24 則判成中性、14 則判成正面。預警只看負向偏離，這個落差不能忽略。
- 速度：CPU 每則 15.4 毫秒（批次 64；逐則 24.6 毫秒），GPU 每則 0.34 毫秒。線上 Gemma 4 每則約 1.4 秒，且標題要送到雲端。
  訓練一次 107 秒（單張 RTX 5070 Ti）。
- 這裡的「一致率」是與語言模型一致，不是準確率：台股中文標題沒有人工標注可對照。

## 解讀與限制

- **驗證集高估了表現。** 學生在驗證集的一致率 87.5%、κ 0.773，到兩週後的測試集降為 81.8%、κ 0.639。
  驗證集是同一期間內隨機抽出的標題群組，看不到時間漂移；之後的實驗應改用時間切分的驗證集。
- balanced class weight 已經加重負面的權重，負面召回率仍只有 66%。要提高，需要更多負面樣本或調整判定門檻；
  門檻必須在新的時間切分驗證集上決定，不能用這次的測試集挑。
- 學生會連教師的錯一起學；教師本身沒有台股中文的人工標注驗收。
- 測試只有兩週、113 則負面，只跑一個 seed。
- 教師標籤經 Gemini API 取得，條款與立場見 [DATA_SOURCES.md](../DATA_SOURCES.md)。學生沒有接上線上系統，網站的評分器不變。

## 下一步（尚未執行，各自需要新的預先聲明）

1. **擴充訓練資料。** 線上評分持續累積；2024-07 至 2025 年只有 gemma3:27b 評過的 3,468 則歷史標題，
   改以自行部署的 Gemma 4（Apache-2.0）重新評分後加入，也一併避開 API 條款的疑慮。
2. **大小模型串接。** 學生先處理全部標題，負面機率超過某個門檻的才送語言模型複核。
   門檻在時間切分的驗證集上決定，目標是負面召回率至少 80%，同時讓送審比例盡量低。
3. **以人工標注驗收。** 台股中文標題的人工盲標完成後，學生與教師都對人工標注計分，回答「準不準」，而不只是「像不像」。
